## 配置速查

完整配置在插件配置面板里改，也可以直接编辑插件目录下的 `config.toml`。

**面板与字段的对应关系**：配置面板按 12 个分组展示，每一组对应 `config.toml` 里的一个段。改文件时先看这张表：

| 面板分组 | config.toml 段 |
| --- | --- |
| 启用插件 / 配置版本 | `[plugin]` |
| 仿真与存档 | `[sim]` |
| 睡眠 | `[sleep]` |
| 月经周期 | `[cycle]` |
| 运动 | `[exercise]` |
| 主动播报 | `[speech]` |
| 急救 | `[rescue]` |
| 日程联动 | `[link]` |
| 聊天喂食 | `[feeding]` |
| 排泄 | `[excretion]` |
| 情绪感知 | `[emotion]` |
| 体感冲突校正 | `[conflict]` |
**`config.toml` 不在仓库里**：宿主第一次加载插件时会按 `config.py` 里的默认值自动生成它。这样做是为了让你升级插件时能拿到新的默认值，而不是卡在旧快照上。下面这份就是生成出来的样子。

```toml
[sim]
dt = 10.0                    # 单步推进多少仿真秒
speed = 1.0                  # 时间倍率，2.0 = 两倍速
follow_system_clock = true   # 用系统时间校准仿真钟点
catch_up_max_hours = 8.0     # 重启后最多补算几小时
autosave_seconds = 30.0      # 存档间隔
history_limit = 2200         # 曲线采样点上限
seed = 20261106              # 随机种子，决定食物搭配等

[sleep]
start_hour = 23.0            # 入睡时刻
end_hour = 7.0               # 起床时刻
wake_on_message = true       # 夜里被消息叫醒
wake_hold_minutes = 10.0     # 醒后要安静多久才重新入睡
block_while_asleep = false   # 睡着时完全不响应消息
force_sleep_after_hours = 20.0   # 连续清醒多久强制入睡，0 = 关闭
force_sleep_hours = 6.0          # 强制睡眠持续多久
force_sleep_wakeable = true      # 强制睡眠期间能否被消息叫醒

[cycle]
enabled = false              # 默认关：关闭时不产生任何效果
cycle_length = 28.0          # 周期长度（天）
period_length = 5.0          # 行经天数
pain_enabled = true          # 行经时是否痛经
last_period_date = ""        # 上次月经开始那天，如 2026-01-01 或 2026/01/01；留空 = 从启用那刻累加

[exercise]
enabled = true               # 按日程摘要自动进入运动（身体不合适时会拒绝）
max_minutes = 45.0           # 单次最长分钟数
interval_minutes = 15.0      # 间歇节奏
min_energy = 55.0            # 精力门槛
min_sleep_hours = 6.0        # 最近睡眠不足这个数不运动

[rescue]
enabled = false          # 默认关：开箱即用不替使用者决定送不送医
threshold = 25.0         # 健康值低于这个算病重（0~100）
critical_seconds = 600.0 # 病重持续多久才送医（仿真秒），0 = 立刻送
stay_hours = 6.0         # 住院多久（仿真小时）
restore_health = 74.0    # 出院时健康值恢复到多少（0~100）
silent_hours = 0.0       # 住院头几小时不回消息，0 = 不拦

[feeding]
enabled = false              # 默认关：聊天喂食需要主动开启；关闭时 body_eat 不进常驻工具表
trust_private_only = false   # 只在私聊里认喂食（群聊会被拒绝，并在回复里说明）

[excretion]
show_urination = true   # 关掉就不播报排尿事件
show_stool = true       # 关掉就不播报排便事件

[speech]
proactive_enabled = false      # 未实现：面板已置灰，改它不会有任何行为
min_interval_minutes = 120.0   # 同上，预留给将来的播报节流

[link]
enabled = false              # 总开关：开启后才与日程插件联动
provider = "life"            # 麦织填 weave，麦生活填 life
sync_activity = true         # 按日程的睡眠与活动调心率、体温、血压
sync_meal = true             # 三餐改由日程触发
inject_state = false         # 请求模型前注入体征（须联动开启；仅异常时注入才花 token）
sync_clock = false           # 用麦生活时钟校正仿真钟点（仅麦生活）
share_state = false          # 住院/病危时通知麦生活（唯一写接口；麦织不支持）
interval_seconds = 60.0      # 拉取间隔，不建议低于 30
weather_enabled = true       # 抓取室外天气
weather_city = "北京"
weather_refresh_seconds = 1800.0

[emotion]
enabled = false          # 默认关：开启后用内置词典分析麦麦自己说的话
scale = 1.0              # 情绪强度倍率，1.0 为标定值
max_valence = 60.0       # 单句最多能写入多少情绪
min_chars = 4            # 短于这个字数不判
cooldown_seconds = 3.0   # 两次判定之间的最小间隔（秒），防连续短消息叠爆

[conflict]
enabled = true           # 默认开：胃已排空但不饿时，补一句校正
hunger_floor = 65.0      # 饥饿低于这个数才算「不算饿」
gastric_idle_ml = 150.0  # 胃内容物低于这个体积才算「已排空」
```

**`[speech]` 目前是未实现项**：`proactive_enabled` 与 `min_interval_minutes` 在插件代码里**没有任何读取点**，改它们不会产生任何行为。面板已按未实现置灰（不可切换），保留字段是为将来「身体自述主动播报」预留。

容易混淆的是联动里的「主动分享」：那是 `[link] share_state`，在住院或首次濒危时把事件交给麦生活的机会池，由麦生活决定发不发 —— 与本段的「主动播报」是两回事。

**`[feeding]` 与工具可见性**：`enabled = false` 时，`body_eat` 会被降为 deferred —— 名字与短描述仍可被 tool_search 发现，但完整参数说明不再进每次请求的常驻工具表（约省 250 token/次）。宿主只此一项判定，**改完需重载插件**才生效。

**`trust_private_only`**：打开后只认私聊投喂。判定依据是宿主传给工具处理器的 `group_id` 与会话名，群聊里会明确回「当前是群聊，这次没有记」，而不是静默失败。v1.3.0 之前这个开关打开会拒绝**全部**投喂，已修正。

两个 `excretion` 开关**只管事件流播不播报**。体液、残渣、膀胱容量和次数统计照常算，水平衡不受影响。改完即时生效。

`[emotion]` 默认关闭。开启后插件在麦麦每次回复之后，用内置情感词典判一次正负与强度，写进瞬时效价（`mood_valence`，约 6 分钟自衰减回 0）。全程本机完成，**不调用模型、不联网、不消耗 token**。判定基于规则词典：反讽、网络新梗会判错，对话体自评约 90%（同集自评，真实泛化未验证）。`cooldown_seconds` 用来防止「嗯」「哦」这类连续短消息把情绪叠爆。建议先开几天，看日志里的「情绪自评」几行判得靠不靠谱，再决定是否长期开启。

`[conflict]` 是本插件对**外部来源**的一处被动校正，默认开启。

背景：日程插件（麦生活）自己维护一套 `hunger` 与 `health_note`，与身体模型的数值互不同步。
它的 `health_note` 在它自己的 `hunger > 88` 时写「有些饿，胃里空空的」；而身体这边可能刚消化完、
胃已排空却并不觉得饿。两句话同时进模型上下文，就会出现「不饿，但胃是空的」这种现实里没人会说的话。

**我们只改自己这一侧**：在注入的提示里补一句 `【身体】刚消化完，胃空但不饿。`（15 字，只陈述事实、不写禁止式指令），不修改、也不要求其他插件适配。
判据是三者同时成立：开关打开、胃内容物低于 `gastric_idle_ml`、饥饿低于 `hunger_floor`。
「胃空且确实饿」是一致的，不校正；不冲突时这段完全不注入，不占上下文。

本段的开关**独立于** `[link] inject_state`：即使关掉常规体征注入，校正仍然生效。
若觉得多余，把 `enabled` 设为 `false` 即可。

`[rescue]` 里 `threshold` 必须小于 `restore_health`。写反了（例如阈值 95、出院恢复 74）会导致第一次住院之后急救再也不触发——出院后健康停在 74，始终超过不了 95，急救状态无法重新上膛。插件会自动把 `restore_health` 抬到阈值之上并打一条 warning，但最好还是别这么配。

`dt` 默认 10 秒是最细的实用档。调大不会数值发散（所有一阶惯性环节都做了钳位），但曲线精度会掉。`follow_system_clock` 关掉后仿真钟点只按仿真时长走，和真实时间的偏差会一直累积，一般不建议关。
