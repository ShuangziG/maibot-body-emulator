# 麦麦身体 v1.3.2 更新报告

> 报告日期：2026-11-23　｜　基线版本：v1.3.1　｜　本次版本：**v1.3.2**
>
> 本版是修 bug 的一版：让体征曲线在长时间运行后不再整块消失，并让曲线本身可读
> （刻度可见、单点可读、体温不再画成锯齿）。另把日程联动的引擎选择从手填改成自动识别。
> 不新增生理字段、不改动力学公式 —— 存档与配置向后兼容。

## 一、这次做了什么

### 1.1 修复

| 问题 | 原因 | 处理 |
|---|---|---|
| 身体跑满约 16 小时后，体征曲线整块空白 | 宿主对插件 WebUI 接口的返回值上限是 **20000 个 JSON 元素**；18 条序列 + 时间/天数/分期 3 列 ≈ **21 元素/点**，24 小时窗口 1440 点 ≈ **3.0 万**，超了三成，接口被判失败 | 新增 `body/history.py`：统一按 **19000 元素预算**等间隔降采样（下限 24 点），`webui_history` 全部改走 `build_history_payload` |
| 时间线页 48 小时档报「JSON 超过 20000 个元素」 | 同上（窗口越长点越多） | 同上；24/48/72 小时三档都在预算内 |
| 曲线两侧的刻度数字看不见 | 刻度与坐标轴共用同一个颜色变量，浅色主题下与背景几乎同色 | 新增 `--chart-label`（浅色 `#6e6d68` / 暗色单独取值） |

| 月经周期关闭时，睡眠卡片右侧留一块空白 | 两列网格写死 | 关闭时卡片占满整行 |
| 曲线卡片标题写「近 12 小时体征」 | 页面一直请求 24 小时 | 标题改为「近 24 小时体征」 |

## 二、为什么做

**曲线为什么整块消失。** 宿主给 WebUI 接口的返回额度是 20000 个 JSON 元素。体征曲线每个
采样点带 18 条序列，再加时间、天数、睡眠分期三列，合计 21 个元素；24 小时窗口 1440 个点，
约 3.0 万个元素 —— 超了三成，接口直接失败，前端只能整块空着。不是「有时会错」，
是「跑到约 16 小时必然出错」。

**为什么看起来像偶发。** 存档只保留最近 600 个采样点，重启后从 600 点恢复，要再攒够 951
点才重新越线（约 5.8 小时）。所以症状是「重启后正常一阵，跑够了就报错」，很像随机故障，
其实完全可复现。

**刻度为什么看不见。** 刻度数字与坐标轴共用同一个颜色变量，浅色主题下那颜色和背景几乎同色
—— 数值一直在画，只是被藏住了。

**日程引擎为什么改成自动。** 「装的是麦生活还是麦织」是环境事实，不该让用户手填一个可能填错的
字符串；填错时联动会一直失败、身体退回独立运行，而界面上看不出原因。改为自动探测后，
界面上显示的是**实际连上的那个**。

## 五、已知边界

| 项 | 说明 |
|---|---|
| 降采样会降分辨率 | 长窗口（48/72h）会以等间隔抽点，曲线上短暂尖峰可能被抽掉；24h 档在 1440 点以内仍是全分辨率 |
| `weave` 旧配置不迁移 | 显式选过麦织的保持原样（避免把"刻意避开麦生活"的人切走）；只有旧默认 `life` 才按 auto 处理 |
| 分期图取色依赖 CSS 层级 | 变量定义位置变了仍需同步改取色作用域，否则会退回兜底色 |
| `.maibot-release.json` 的 `commit` | 记录「打包基线」的提交号；本版由发布流程回填 |

## 六、发布

1. 合并前跑：`python -B tests/test_history_payload.py`（9 项）与全量 `compile()`。
2. 版本号三处一致（`_manifest.json` / `plugin.py` / `config.py`）。
3. 打 tag `v1.3.2` → 发 Release（正文取 `CHANGELOG.md` 的 v1.3.2 段）。
