## 二、为什么做

### 1. 情绪只有半条轴

原作 LIFE.apk 的症状枚举里 Euphoria（欣快）与 Dysphoria（心境恶劣）是并列的。
本插件此前只有 depression（低落），做得出不开心，做不出开心。

### 2. 激素没有靶点

插件有 cortisol 却没有任何受体字段。激素是钥匙，受体是锁 —— 没有锁，钥匙再多也开不了门。
原作元数据里 Glucocorticoid_receptor 是存在的。

### 3. 外部无法影响情绪

原来情绪层完全内生，没有任何输入口。现在 adjust_mood 支持 valence，
外部（例如对话情感分析）可以按这一句话的情绪写入。

### 4. 三处与情绪无关的缺陷

这一版同时在仓库 issue 里收了三笔账，它们都不是新功能的副产物，而是**一直存在**的问题：

| 问题 | 为什么必须修 |
|---|---|
| 心电/脑电面板空白（#11） | 接口与前端声明都在，只有绘制代码在某次页面重建中丢失。功能「看起来还在」，实际什么都不显示，最容易长期不被发现 |
| 「给你点份外卖」不记账（#12） | 工具描述把「已经吃完」写成了调用前提，模型据此判断尚未发生。投喂链路于是**静默失效**，比报错更难查 |
| 「仅私聊认喂食」一开就全拒 | 开关打开的语义是「限制来源」，实际效果却是「关掉功能」。使用者会以为自己配错了 |

三者的共同点：**都不报错**。所以这次除了修，也在 4.5 里留下了可复跑的判据，
避免同类问题再靠肉眼发现。

## 四、验证证据

### 4.1 零影响（最关键）

未写入外部情绪时，改动前后的 24 小时仿真逐位一致：

| 指标 | 最大偏差 |
|---|---|
| 压力 | 0.000 |
| 心境 | 0.000 |
| 皮质醇 | 0.000 |
| 肾上腺素 | 0.000 |
| 精力 | 0.000 |
| 饥饿 | 0.000 |

原因：mood_valence 默认 0，其耦合项恒为 0；r_gcr 只计算不参与压力计算。

### 4.2 三次独立运行（不同随机种子）

| 指标 | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---|---|---|
| 效价区间 | -59.1 到 59.7 | -59.7 到 59.5 | -59.3 到 59.1 |
| 欣快峰值 | 66.3 | 65.1 | 64.9 |
| 烦躁峰值 | 61.1 | 62.0 | 61.3 |
| 压力区间 | 15.6 到 34.9 | 17.4 到 43.6 | 17.5 到 36.7 |
| 皮质醇区间 | 0.525 到 0.997 | 0.525 到 1.080 | 0.525 到 1.002 |

三次形态一致、仅相位不同，说明机制稳定。

### 4.3 相关性

| 关系 | 三次系数 | 是否符合设计 |
|---|---|---|
| 皮质醇与压力 | +0.84、+0.89、+0.85 | 是（HPA 轴应有的样子） |
| 效价与欣快 | +0.73、+0.59、+0.69 | 是 |
| 效价与烦躁 | -0.57、-0.75、-0.63 | 是（心情好时不烦躁） |
| 压力与烦躁 | +0.33、+0.55、+0.40 | 是 |

### 4.4 边界与压力测试

| 输入 | 结果 |
|---|---|
| 效价正负 1e9、正负 1e-12、正负 100 | 无崩溃、无越界 |
| 极端快速交替（正负 100 每 30 秒，200 轮） | 无发散；但欣快与烦躁会同时偏高，见第五节 |
| 仿真步长 0.001 到 1000 秒 | 无崩溃、无越界（限幅有效） |
| 7 天长程 | 激素无漂移，终态皮质醇 0.836 |

不变量检查（有限性、受体在 0 到 1、体感在 0 到 100、效价在正负 100）：违规 0 条。

## 六、兼容性

- 新增 `[emotion]`（5 项，默认关闭）与 `[conflict]`（3 项，默认开启）两个配置段；
  老配置文件缺这两段时按默认值补齐，可直接用，面板会多出对应分组。
- 存档字段只加不删，body_state.json 不需要重建。
- adjust_mood 旧调用方式（stress_delta、mood_delta 等）不受影响；新增的 `valence` 为可选参数。
- **发布包不再包含 `config.toml`**（与仓库口径一致：它由宿主首次加载时按默认值生成）。
  若同目录残留旧的 `config.toml`，宿主会按其中的 `config_version` 走迁移，
  用户改过的值会保留；但用陈旧模板整包覆盖会把这部分值顶回默认，部署时请排除该文件。
- `body_eat` 的可见性在插件加载时确定，**改动「允许聊天喂食」后需重载插件**才生效；
  不影响其它任何功能，也不影响已在常驻表里的其它工具。
- 本报告只描述代码变化，部署副本的同步状态以实际部署为准。

## 八、下一步建议

1. 用真实聊天记录验证情绪判定准确率，再决定是否长期开启「情绪感知」。
2. 长期心境若要表达跨天跨周的抑郁，需在 6 小时积分之外再加一层日尺度积分。
3. 之后再考虑 CNS_Reward 与多巴胺受体（需要先定多巴胺的量纲）。
4. **issue #9（年龄可配）**：`age` 目前是内置常量 18。若开放配置，须同时接到心率基线与 HRmax、
   运动能力门槛、恢复速率，否则会出现「60 岁的身体跑 18 岁的配速」这种自相矛盾。
5. **issue #10（运动烈度）**：现在所有运动都归一到慢跑。要做对，需要可靠来源（日程的结构化烈度字段），
   靠关键词解析「冲刺」「慢跑」容易被幻觉带偏。
6. **issue #7 / #5**：外部投喂插件的接管姿势（文档口径）与跨插件生理干预接口（新 API），属功能设计，
   建议先定接口契约再动手。
